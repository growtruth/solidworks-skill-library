> 日期：2026-11-08　范围：第一轮零件实战（旋转特征 + 切除特征）

## 2. 本轮踩的坑与根因

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| 1 | PowerShell 连 SolidWorks 一切成员报 `TYPE_E_ELEMENTNOTFOUND` | 本机 .NET/IDispatch 绑定异常 | 锁定 VBScript 单通道，放弃 PowerShell |
| 2 | `OpenDoc6` 报类型不匹配 | ByRef 出参在 VBScript 无法传递 | 每个脚本从新建文档一次跑完 |
| 3 | `SaveAs2` 返回 0 但文件存在 | 返回值不可靠 | 用 `FileExists` 判断 |
| 4 | 画 6 个圆，草图只剩 1 个 | 用了模型坐标；上视基准面草图需 `(x, z, 0)` | 统一改用草图局部坐标 |
| 5 | `FeatureCut4` 返回 `Nothing`、体积不变 | 切除默认方向与草图法线相反 | `Dir=True` 反向切除 |
| 6 | 普通零件设 `NormalCut=True` 导致失败 | 该参数仅钣金有效 | 一律 false |
| 7 | `UBound(...)` 报错 | dispatch 数组不支持 UBound | 用 `For Each` 或体积校验替代 |
| 8 | 特征名写死英文选不中 | GB 模板名称是中文 | 遍历 `RefPlane` 序号取面 |

## 3. 流程层面的改进（已写入 SOP / 避坑清单）

1. **先算体积再建模**：建模前手算解析体积，建模每一步后立刻比对，问题当场暴露，不用等出图才发现。
2. **一脚本一零件**：因无法重新打开文档，所有步骤必须串在一个脚本内完成。
3. **坐标系先确认**：动笔画草图前先确定“哪个基准面对应哪两个坐标分量”，能消灭一半的草图失败。
4. **方向类参数单独验证**：切除/拉伸的方向、薄壁的偏移方向，先小步验证再复用。

## 4. 本轮暴露的能力缺口（按优先级）

1. **圆角/倒角特征未落地**：三个零件都没有倒角，工业图纸上这是必检项。→ 下一轮先做 `FeatureFillet3` / 倒角 API 实验。
2. **圆周阵列未实测**：本轮 6 孔/4 孔用“一次草图多圆”绕过阵列。功能正确，但设计意图差（改孔数要改草图）。→ 改用“单孔 + 圆周阵列”，并验证 API 选择标记（轴=1，特征=4）。
3. **没有材料与质量**：只算体积。→ 增加材料赋值，输出质量/密度核对。
4. **键槽尺寸未对标 GB/T 1095**：当前 12×5 是示例值，未查标准表。→ 补标准表并在 SOP 中引用。
5. **齿轮未开始**：渐开线齿廓需要方程式驱动或逐点拟合，是三种零件里难度最高的一个。→ 单独立项，先做齿廓数学模型再建模。
6. **装配与工程图完全未涉及**：能力基线表的“未验证”一栏仍为空。

## 7. R2 迭代记录（2026-11-09）

**目标**：把法兰从“单草图多圆”升级为“单孔 + 圆周阵列”，并加外缘 C2 倒角。

| 步骤 | 理论体积 (mm³) | 实测体积 (mm³) | 偏差 |
|---|---|---|---|
| 旋转基体（含 2×45° 倒角剖面） | 180092.9 | 180092.8 | 0.00006% |
| 单孔 φ14 切除 | 177630.0 | 177629.8 | 0.0001% |
| 6 实例圆周阵列 | 165315.5 | 165314.8 | 0.0004% |

**验证通过的 API**
- `FeatureCircularPattern4(6, 2π, False, "NULL", False, True, False)`：种子特征用 `BODYFEATURE` + 标记 4，方向轴用同心圆边 `("", "EDGE", x,y,z, True, 1, ...)` + 标记 1，等间距传总角度。

**未解决的 API**
- `InsertFeatureChamfer(0, 0, 0.002, 0.785, 0.002, 0, 0, 0)` 返回特征、特征数增加，但体积完全不变（边未挂上，`EdgeCount=0`）。本轮改用剖面 2×45° 倒角，几何等价且可解析校验。倒角特征 API 列入 R2.1 待办。

**性能处理**
- 建模前杀掉残留 SLDWORKS 实例；全程只启动 1 次 SolidWorks；脚本末尾 `CloseDoc + ExitApp`。
- 空闲内存 3.20 GB → 3.81 GB（释放约 0.6 GB），无残留实例（仅 7 MB 的 `sldworks_fs` 助手）。

## 8. R3 迭代记录（2026-11-09）

**目标**：给法兰赋材料，用“体积 × 密度”校验质量。

**结果：材料 API 未生效（记为已知限制）**

| 尝试 | 调用 | 结果 |
|---|---|---|
| 1 | `SetMaterialPropertyName2(cfg, "SolidWorks Materials", "普通碳钢")` | 密度仍 1000，材料名为空 |
| 2 | 默认库（数据库传空字符串） | 密度仍 1000 |
| 3 | 全路径 `...\solidworks materials.sldmat` | 密度仍 1000 |
| 4 | 实体级 `IBody2.SetMaterialProperty("solidworks materials.sldmat", ...)` | 密度仍 1000 |

过程中修正了两个语法坑：该方法/实体方法都是 **Sub**，不能加括号、不能赋值给变量；中文材料名必须用 `ChrW` 拼接（`.vbs` 文件保持 ASCII，否则 WSH 报“无效字符”）。

**替代方案（已落地）**：质量用解析法。法兰 R2 体积 165314.8 mm³ = 165.3148 cm³，普通碳钢密度 7.845 g/cm³ →
`Mass = 1296.9 g ≈ 1.297 kg`。质量属性 API 的默认密度 1000 kg/m³ 下 `Mass = 0.1653 kg`，与体积换算一致，说明“体积→质量”链路本身是正确的，问题只在材料赋值。

**性能处理**：本轮共 5 次单实例启动，每次结束都 `ExitApp`；两次因脚本异常残留的实例被强制结束，最终空闲内存 3.92 GB、无残留。
